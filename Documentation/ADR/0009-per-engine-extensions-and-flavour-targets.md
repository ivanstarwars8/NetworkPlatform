# ADR-0009. Расширение на каждый движок, цель приложения на каждый вариант сборки, общий слой мостов

- Статус: **принято** (обратимое решение уровня реализации)
- Дата: 2026-11-27
- Уточняет: ADR-0001 §3 (правила 1, 3, 5) — как они выражены в проекте Xcode; ADR-0004 §2.3 (карта модулей) и строку
  «Разделение на `XrayOnly` / `MihomoOnly` / `Dual` выражается только xcconfig, без дублирования целей» (ADR-0004, §3).
- Код: `Apps/project.yml`, `Apps/Configurations/*.xcconfig`, `Extensions/PacketTunnel/BridgeBinding.swift`,
  `Extensions/PacketTunnel/Shared/TunnelEngineCatalog.swift`, `Apps/SharedApp/TunnelController.swift`,
  `Packages/EngineBridge`, `Packages/EngineXray`, `Packages/EngineMihomo`, `Tools/apple-build-flavour.sh`,
  `.github/workflows/apple.yml`.

## 1. Контекст

ADR-0001 требует: один движок на процесс расширения, приложение не линкует Go, `Dual` = два расширения, выбор
расширения — через `providerBundleIdentifier`. До этого этапа в проекте было одно расширение (`PacketTunnel`) и одна
цель приложения на платформу; `MihomoOnly` и `Dual` останавливались фазой «Flavour guard», потому что моста Mihomo под
Apple не было.

Ограничение Xcode [U, по опыту, не по документации]: зависимости цели и встраивание расширений (фаза копирования
`PlugIns`) не зависят от конфигурации сборки. Одна цель приложения, которая встраивает «расширения своего варианта»,
либо встраивает и собирает оба расширения во всех вариантах (тогда `XrayOnly` собирает GPL-код и требует артефакт
Mihomo), либо встраивает их сценарием в обход Xcode (ручной порядок сборки схемы, своя копия и подпись бандлов).

## 2. Решение

1. **Цели расширений — по движку**, не по варианту: `PacketTunnelXray_<p>` (EngineXray + `NPXrayBridge.xcframework`)
   и `PacketTunnelMihomo_<p>` (EngineMihomo + `NPMihomoBridge.xcframework`). Исходники общие
   (`Extensions/PacketTunnel`); каждая цель компилируется ровно с одним условием движка (`NP_ENGINE_CONDITIONS`
   уровня цели перекрывает условия варианта), поэтому даже в `Dual` расширение Xray не видит модуль Mihomo и наоборот.
   Привязка C ABI (`BridgeBinding.swift`) — один файл для обоих мостов: экспорт `npb_*` у мостов одинаковый
   (`Cores/MihomoBridge/cabi/shape_test.go`), различается только импортируемый модуль.
2. **Цели приложения — по варианту**: `AppXrayOnly_<p>`, `AppMihomoOnly_<p>`, `AppDual_<p>` из одного шаблона XcodeGen;
   различаются только встраиваемыми расширениями. Вариант по-прежнему задаётся xcconfig (условия компиляции,
   `NP_FLAVOUR`); фаза «Flavour guard» теперь проверяет соответствие: цель приложения собирается только своей
   конфигурацией, расширение — только в варианте, где есть его движок. Схемы: `NetworkPlatform-<вариант>-<платформа>`.
   Это отступление от строки ADR-0004 «без дублирования целей»: дублирования исходников и настроек нет (шаблон), но
   целей приложения три на платформу.
3. **Идентификаторы**: расширения `<prefix>.PacketTunnelXray` и `<prefix>.PacketTunnelMihomo` (было `<prefix>.PacketTunnel`).
   Приложение знает движки своей сборки по условиям компиляции (`TunnelEngineCatalog.thisBuild`) и перед стартом
   переписывает `providerBundleIdentifier` единственной VPN-конфигурации на расширение движка из запроса
   (ADR-0001, правило 5; проверка E-3 — на устройстве).
4. **Общий слой мостов** — модуль `EngineBridge` (чистый Swift, Go не линкует): протокол C ABI (`BridgeABI`), коды и
   конверт ответов, драйвер жизненного цикла (`BridgeEngineDriver`: блокирующие вызовы на своих потоках, прерывание
   старта через `npb_stop`, насос пакетов, чтение журнала, сторож, здоровье, нормализация ошибок),
   `PacketTunnelFlowIO`. `EngineXray` и `EngineMihomo` содержат только различия движков: формат конфигурации,
   опции моста, сводку проверки, форму статистики. Приложение `Engine*` не линкует (ADR-0004 §2.3, правило 3).
5. **Проверки CI** (`Tools/apple-build-flavour.sh`): в приложение встроены ровно расширения варианта; в каждом
   расширении есть символы `npb_*`, пути пакетов своего ядра (`github.com/xtls/xray-core` или
   `github.com/metacubex/mihomo`) и своего адаптера, и нет чужих; в бинарнике приложения нет ни `npb_*`, ни путей
   пакетов ядер, ни адаптеров.

## 3. Последствия

- `XrayOnly` не собирает и не содержит кода Mihomo (GPL-3.0); проверяется CI по содержимому бинарников.
- Документы и план проверки на устройстве ссылаются на новые имена схем, целей и идентификаторов.
- Если два расширения packet-tunnel в одном приложении окажутся недопустимы (E-3, ADR-0001 §2C), `Dual` не выпускается,
  а `XrayOnly`/`MihomoOnly` остаются без изменений.
- Вернуться к одной цели приложения можно, если появится способ встраивать расширения по конфигурации средствами Xcode;
  код от этого не зависит, меняется только `project.yml`.
