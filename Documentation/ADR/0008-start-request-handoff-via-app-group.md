# ADR-0008. Передача запроса запуска файлом в App Group

- Статус: **принято** (обратимое решение уровня реализации; фиксирует то, что уже написано и протестировано на Linux)
- Дата: 2026-11-27
- Заменяет: ADR-0003 §3.1, строку «Конфигурация», и ADR-0003 §3.3 п. 1 («готовый документ передаётся в `startVPNTunnel(options:)`»). Остальное в ADR-0003 §3.3 (снимок у расширения, On-Demand) не меняется.
- Код: `Extensions/PacketTunnel/Shared/ConfigurationHandoff.swift`, `TunnelMessages.swift` (протокол IPC v2), `Extensions/PacketTunnel/ConfigurationSnapshotStore.swift`, `Extensions/PacketTunnel/PacketTunnelProvider.swift`, `Apps/SharedApp/TunnelController.swift`. Тесты — `Packages/CoreAbstraction/Tests/TunnelIPCTests.swift` (через символическую ссылку `SharedIPC`).

## 1. Контекст

ADR-0003 предполагал передавать скомпилированный конфиг прямо в `startVPNTunnel(options:)`. Конфиг Xray с маршрутизацией
может занимать мегабайты (ограничение проекта — 8 МиБ, `CoreConfiguration.maximumPayloadBytes`). Какой объём система
пропускает через опции запуска, Apple не документирует, и проект это не измерял [U]. Опции к тому же проходят через
системный процесс, а не напрямую в расширение. Поэтому поток swiftaudit (этап 2) реализовал передачу файлом в общем
контейнере App Group. Это расходится с ADR-0003, а `STATUS.md` §3 и `CLAUDE.md` требуют записать решение. Этот ADR его записывает.

## 2. Решение

1. **Опции запуска несут только ссылку.** `TunnelStartReference` = `{version, handoffID, byteCount, sha256}`. Это JSON
   под ключом `np.start-reference`, не больше 1024 Б (`TunnelIPC.maximumStartReferenceBytes`, ограничение проекта).
   `handoffID` — канонический UUID. Проверка этого поля не даёт ссылке указать путь вне каталога передачи.
2. **Запрос лежит в файле** `<контейнер App Group>/StartHandoff/<handoffID>.start`. Формат — контейнер `TunnelStartContainer`
   v1: `"NPSTART"` + байт версии, длина заголовка (4 Б, big-endian), JSON-заголовок (движок, метка формата, сетевой
   план), дальше конфиг движка как есть, без base64. Ограничения проекта: конфиг до 8 МиБ, заголовок до 16 КиБ.
3. **Запись.** Каталог создаётся с правами `0700`, файл пишется атомарно. На iOS/iPadOS/tvOS/visionOS файлу ставится
   класс защиты `completeUntilFirstUserAuthentication` (файл должен читаться при On-Demand после первой разблокировки).
   Сообщение об ошибке записи содержит только тип ошибки, без пути и содержимого.
4. **Однократное чтение.** Расширение проверяет ссылку, читает не больше `byteCount + 1` байт и сверяет длину и
   SHA-256. Файл удаляется при любом исходе. Обрезанный, подменённый, устаревший или чужой файл отвергается
   (`handoff_corrupt`, `handoff_missing`, `handoff_too_large`, `malformed_start_reference`).
5. **Остатки.** Файлы старше 600 с (`ConfigurationHandoff.staleAfter`) — следы запусков, которые не состоялись. Их
   удаляет приложение перед записью и расширение после чтения. Удаление со стороны расширения добавлено вместе с этим
   ADR. Если система отказала в `startVPNTunnel`, приложение удаляет свой файл сразу (`discard`).
6. **Снимок остаётся у расширения** (ADR-0003 §3.3 п. 2–3). Он лежит в собственном контейнере расширения, не в App
   Group, и использует тот же формат контейнера, поэтому повреждённый снимок тоже отвергается. На tvOS он лежит в
   caches и может пропасть. Тогда запуск без приложения завершается понятной ошибкой.
7. **Целостность, а не секретность.** Файл содержит секреты в открытом виде, как и снимок (риск R-14). Защита — контейнер
   группы, класс защиты, права каталога и короткое время жизни (секунды между записью и чтением). Хэш в ссылке
   защищает от подмены и рассинхронизации, но не от чтения.
8. **Имя группы не вычисляется в коде.** Его берут из ключа Info.plist `NPAppGroupIdentifier`. Ключ заполняется из
   настройки сборки `NP_APP_GROUP` в обеих целях (`Apps/project.yml`): `group.<id>` на iOS, tvOS и visionOS,
   `<TeamID>.<id>` на macOS.
9. **Область действия — упаковка app extension на всех платформах, включая macOS.** Именно её собирает
   `Apps/project.yml`. Вариант macOS с system extension (Developer ID, ADR-0005 «system extension first») этим ADR не
   покрыт. Доступ system extension к контейнеру группы пользователя не подтверждён (ADR-0003 §3.3). Когда этот вариант
   появится, ему нужен свой канал передачи (кандидаты: ссылка в опциях + XPC, или конфиг в опциях, если измеренный
   предел позволит). Пока на macOS собирается app extension. Это отступление от порядка ADR-0005, его надо пересмотреть
   вместе с вариантом system extension.

## 3. Отвергнутые варианты

- **Конфиг целиком в опциях запуска** (исходный ADR-0003). Предел объёма неизвестен. Ошибка проявилась бы только на
  больших профилях и только на устройстве.
- **Передача через `sendProviderMessage` после запуска.** Расширению пришлось бы стартовать без конфига и ждать
  сообщения. Запуск системой (On-Demand) так не работает, и появляется лишнее состояние «запущено, но пусто».
- **Unix-сокет или loopback в App Group.** ADR-0003 запрещает сетевые сокеты между процессами. Сокет решает задачу
  потоковых данных, а не одной передачи.

## 4. Следствия

- Протокол IPC — версия 2. Старые JSON-снимки (до формата контейнера) игнорируются (`STATUS.md` §3).
- Расширению нужен доступ к App Group на всех платформах. Без группы (`handoff_unavailable`) запуск из приложения
  невозможен. Запуск системой по снимку возможен.
- Правило `CLAUDE.md` «Запрос запуска передаётся файлом в App Group — нужен ADR» закрывается этим ADR.

## 5. Что надо доказать на устройстве

| № | Проверка | Где |
|---|---|---|
| H-1 | расширение iOS/iPadOS читает и удаляет файл, записанный приложением, в подписанной сборке с настоящей группой | iPhone/iPad |
| H-2 | после перезагрузки и до первой разблокировки файл с `completeUntilFirstUserAuthentication` не читается, ошибка понятна; после разблокировки On-Demand работает по снимку | iPhone |
| H-3 | изолированное (sandboxed) app extension на macOS читает контейнер `<TeamID>.<id>`, записанный приложением | Mac, подпись с командой |
| H-4 | tvOS: контейнер группы доступен обоим процессам; судьба снимка в caches между запусками | Apple TV |
| H-5 | время от `startVPNTunnel` до `consume` много меньше 600 с, при обычном запуске остатков нет | любое устройство |
