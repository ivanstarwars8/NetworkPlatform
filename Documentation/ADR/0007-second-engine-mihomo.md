# ADR-0007: второй движок — Mihomo

- Статус: принято окончательно владельцем проекта 2026-11-27. Движки проекта — Xray-core и Mihomo.
- Сравнительные бенчмарки пяти ядер отменены владельцем 2026-11-27 (решение не зависит от них).
- Заменяет в планах: sing-box как второй движок (ADR-0001 §набор движков).

## Контекст

Первый движок — Xray-core (ADR-0001). Вторым кандидатом был sing-box. Аудит по исходникам
(`Documentation/Research/mihomo-leaf.md`, `shoes.md`, `v2fly-dae-hysteria.md`) показал:

- Mihomo покрывает больше клиентских протоколов, чем остальные кандидаты, включая XHTTP с раздельной отдачей,
  Hysteria2, TUIC, WireGuard/AmneziaWG, и даёт родной формат Clash с группами и провайдерами правил.
- Shoes не заменяет sing-box по функциям; Leaf, v2fly, dae и официальная Hysteria как движки не подходят.

## Решение

Вторым движком проекта становится Mihomo. sing-box остаётся изученной альтернативой и не интегрируется,
пока нет причины вернуться к нему.

Неизменно из ADR-0001: один движок на процесс Packet Tunnel, каждый движок — отдельное расширение,
переключение движков перезапускает туннель.

## Следствия

- **Лицензия.** Mihomo распространяется под GPL-3.0 (ветка `Meta`). Сборки с Mihomo считаются GPL целиком;
  сборка `XrayOnly` остаётся без GPL. Вопросы ADR-0006 о GPL и App Store теперь относятся к Mihomo и по-прежнему
  открыты.
- **Варианты сборки:** `XrayOnly`, `MihomoOnly`, `Dual` (Xray + Mihomo).
- **Мост пишем сами:** в upstream нет C ABI, gomobile и сборки под iOS.
- **Нужны правки ядра:** вызов `proc_pidinfo` в статистике (непубличный API Apple) убрать; `recvmsg_x` выключать
  настройкой `recvmsgx: false`.
- **Остановка:** у Mihomo нет полной остановки без завершения процесса и состояние туннеля глобальное —
  жизненный цикл расширения должен это учитывать.
- **Конфигурация:** нужен компилятор внутренней модели в Clash YAML с отчётом о потерях (ADR-0002).

## Что остаётся проверить (не условие решения, а инженерная работа)

- Сборка моста Mihomo под платформы Apple и его запуск на устройстве.
- Потребление памяти расширением с Mihomo против лимита iOS (ориентир около 50 МиБ): нужны настройки
  буферов, тайм-аутов простоя и лимита памяти Go, как и для Xray.
- Удаление вызова `proc_pidinfo` и выключение `recvmsg_x` в сборке для Apple.
