# ADR-0002. Внутренняя модель конфигурации, независимая от движков, с отчётом о потерях

- Статус: **принято**
- Дата: 2026-11-24
- Основание: `PROTOCOL_MATRIX.md`, `Documentation/Research/xray.md` §2.5–2.7, `Documentation/Research/reference-apps.md` §4–5

## 1. Контекст

Ни один открытый клиент не имеет собственной модели профиля: hiddify отдаёт сборку конфига ядру и сам не знает итогового результата; Karing строит sing-box JSON в приложении, но этот код закрыт; sing-box-for-apple и OneXray хранят конфиг движка как есть. Все четверо привязаны к одному ядру.

Наборы возможностей движков не совпадают (`PROTOCOL_MATRIX.md` §6). Перевод между ними неизбежно теряет информацию. Пример тихой потери уже есть в самом Xray: на 26.11.9 `KCPConfig.Build()` не читает `header` и `seed`, и старая ссылка mKCP запускается без маскировки.

## 2. Решение

1. **Источник истины — типизированная модель на Swift**, не JSON какого-либо движка. Модель живёт в `DomainModels` и не импортирует ничего, относящегося к движкам.
2. **Конфиг движка — результат компиляции.** Для каждого движка есть компилятор: `модель → (конфиг движка, отчёт)`. Компиляторы живут в `ConfigurationEngine`, работают в приложении, без Go.
3. **Каждая компиляция и каждый импорт возвращают отчёт о конвертации.** Потери не бывают молчаливыми.
4. **Движок не строит и не переписывает конфиг.** Он получает готовый документ. Правило hiddify «не прятать баг ядра в приложении» действует и в обратную сторону: адаптер не чинит конфиг на лету.

## 3. Структура модели

Эскиз, имена предварительные:

```swift
struct Profile            // id, name, source, nodes, routing, dns, tunnel, schemaVersion
struct Node               // id, tag, proxy: ProxyProtocol, stream: StreamSettings, extras
enum   ProxyProtocol      // .vless(VLESS), .vmess, .trojan, .shadowsocks, .hysteria2, .wireguard, …
struct StreamSettings     // transport, security, masks, multiplex, download: StreamSettings? (indirect)
enum   Transport          // .tcp, .websocket, .httpUpgrade, .grpc, .xhttp(XHTTP), .mkcp, …
enum   Security           // .none, .tls(TLS), .reality(Reality)
struct EngineExtras       // [EngineID: JSONValue] — непереводимый остаток, привязан к движку
enum   Quota              // .unlimited, .limited(bytes:)
```

Обязательные свойства:

- **Рекурсия.** `StreamSettings.download` — вложенный `StreamSettings`: у XHTTP `downloadSettings` — полноценный вложенный конфиг со своим адресом, TLS или REALITY и даже другим L4. Плоская модель это не выражает.
- **Непереводимый остаток.** Поля, которых модель не знает, сохраняются в `EngineExtras` под идентификатором движка, из которого пришли (например, `extra` и `h2Params` у XHTTP, экзотические маски finalmask). Они переживают цикл «импорт → хранение → компиляция в тот же движок» и считаются потерянными при компиляции в другой.
- **Типы вместо магических значений.** Квота — `enum`, а не «очень большое число»; режимы — перечисления, а не строки.
- **Секреты отдельно.** Модель хранит ссылку на секрет; значение лежит в Keychain и подставляется при компиляции (ADR-0003).
- **Версия схемы** в каждом сохранённом профиле и явные миграции.
- **Одноимённое с разной семантикой моделируется по смыслу**, а не по полю одного движка: фрагментация ClientHello, обфускация Hysteria2, port hopping, мультиплексор. Компилятор переводит в форму движка: для Xray — маски finalmask, для sing-box — опции TLS и Hysteria2.

## 4. Профиль «как есть»

Пользователь вправе принести готовый конфиг движка и запустить его без переработки. Такой профиль:

- привязан к одному движку и к диапазону его версий;
- не компилируется в другой движок;
- проходит только структурную проверку и подстановку обязательных для туннеля частей (TUN-inbound, fd), о чём сказано в отчёте;
- помечен в интерфейсе как непроверяемый моделью.

Это отдельный вид профиля, а не режим компилятора.

## 5. Возможности движков как данные

`EngineCapabilities` — таблица «движок, версия → протоколы, транспорты, виды защиты, маски». Источник — `PROTOCOL_MATRIX.md`; таблица закреплена за версией движка и обновляется вместе с ней.

Компилятор сверяет профиль с таблицей до генерации. Интерфейс по ней показывает, какими движками профиль может быть запущен. Статус «не заявлено (нет interop-теста)» из матрицы — отдельный признак: узел, чьё сочетание не прошло interop-тест, запускается с пометкой «не проверено», а не скрывается.

## 6. Отчёт о конвертации

```swift
struct ConversionReport {
    var engine: EngineID
    var engineVersion: String
    var issues: [ConversionIssue]
    var verdict: Verdict          // .exact, .degraded, .blocked
}

struct ConversionIssue {
    var path: String              // "nodes[3].stream.masks[0]"
    var kind: Kind                // .unsupported, .approximated, .dropped, .migrated, .engineLocked, .untested
    var severity: Severity        // .info, .warning, .error
    var detail: String
}
```

Правила:

- `.error` у узла — узел исключается; если он был выбран или единственный, вердикт `.blocked` и запуск не выполняется.
- `.warning` — запуск возможен, пользователь видит отчёт до подключения.
- Изменение смысла, влияющее на безопасность или маскировку (потеря обфускации, отключение проверки сертификата, смена транспорта), — всегда не ниже `.warning`.
- `.migrated` фиксирует автоматический перенос. Обязательный случай: `kcpSettings.header`/`seed` → UDP-маска `mkcp-legacy` в `finalmask`.
- Отчёт сохраняется рядом со скомпилированным конфигом и входит в диагностический пакет.
- Отчёт детерминирован: один и тот же профиль и версия движка дают один и тот же отчёт. Это делает его тестируемым.

Импортёры возвращают отчёт того же вида: что распознано, что ушло в `EngineExtras`, что отброшено.

## 7. Импорт

Форматы — данные, не чужой код; реализуются заново на Swift: ссылки (`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` и др.), подписки base64, JSON sing-box, JSON Xray, YAML Clash. Порядок реализации определяется отдельно.

Из референсов берём как контракт:

- заголовки подписки `profile-title`, `subscription-userinfo`, `profile-update-interval`, `support-url`, `profile-web-page-url`;
- явный, настраиваемый `User-Agent` при загрузке подписки.

Не берём: переопределение настроек приложения подпиской без согласия пользователя. Параметры от провайдера показываются как рекомендации с источником и возможностью отказаться.

## 8. Последствия

- Нужно писать и поддерживать два компилятора и набор импортёров. Это основная стоимость решения и основное отличие платформы.
- Новая возможность движка недоступна, пока не добавлена в модель или не пропущена через `EngineExtras`. Профиль «как есть» закрывает разрыв.
- Проверка «примет ли движок этот конфиг» до подключения остаётся неполной: компилятор проверяет по своей таблице возможностей, а не самим движком (риск R-15).
- Тесты компиляторов — эталонные пары «модель → конфиг + отчёт» — запускаются без Go и без устройства.

## 9. Что не доказано

- Что рекурсивной `StreamSettings` и `EngineExtras` достаточно для всех реальных конфигураций XHTTP и finalmask. Проверяется корпусом реальных подписок.
- Что скомпилированный конфиг принимается движком закреплённой версии. Проверяется только запуском (ADR-0001, E-1 и E-2).
- Переносимость узлов между движками для сочетаний из пересечения — только после interop-тестов.
