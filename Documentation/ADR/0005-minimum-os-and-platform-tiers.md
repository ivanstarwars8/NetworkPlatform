# ADR-0005. Минимальные версии ОС и уровни поддержки платформ

- Статус: **принято**; минимум macOS условен до проверки требований Go 1.27
- Дата: 2026-11-24
- Основание: `PLATFORM_MATRIX.md` §1 и §11, `Documentation/Research/singbox.md` §2 и §4, `Documentation/Research/xray.md` §3.3

## 1. Контекст

Источники расходятся:

| Источник | iOS | macOS | tvOS | visionOS |
|---|---|---|---|---|
| Рекомендация `PLATFORM_MATRIX.md` §11 | 17.0 | 14.0 | 17.0 | 1.1 (допустимо 1.0) |
| Текущий `Package.swift` | 16 | 13 | 17 | 1 |
| Сборка libbox upstream | 15.0 | 13.0 | 17.0 | цели нет |
| Сборка libXray, c-archive | 15.0 | 12.0 | 17.0 | цели нет |
| OneXray | 16.0 | 13.0 | — | — |

Факты, от которых зависит выбор:

- NetworkExtension на tvOS появился в 17.0 — ниже невозможно. [V]
- `ProxyConfiguration` и `NERelay` — iOS 17.0 / macOS 14.0; `excludeAPNs` — 16.4 / 13.3; App Intents — iOS 16 / macOS 13. [V]
- Доли iOS 16 и 17 Apple не публикует; известна только доля iOS 26 — 79 % всех iPhone на июнь 2026. [V — через суммаризатор]
- Какую минимальную ОС требует Go 1.27 — не проверено. [U]
- Ни один движок не собирается под visionOS. [V]

## 2. Решение: минимальные версии

| Платформа | Минимум | Почему |
|---|---|---|
| iOS / iPadOS | **17.0** | одна базовая линия с tvOS 17; `ProxyConfiguration`, `NERelay`, `excludeAPNs`, `fetchLastDisconnectError`, App Intents — без веток `#available` |
| macOS | **14.0** | пара к iOS 17 по тем же API; `SMAppService` (13.0) доступен |
| tvOS | **17.0** | жёсткая нижняя граница платформы |
| visionOS | **1.0** | packet tunnel есть с 1.0; добавленное в 1.1 (per-app для управляемых устройств, app proxy, DNS proxy) вне наших целей |

Обоснование выбора 17 / 14 против 16 / 13:

- Проект начинается с нуля; пользователей на старых версиях у него нет.
- Выигрыш в охвате от iOS 16 оценить нельзя — данных нет. Цена известна: ветки `#available` и ещё одна мажорная версия в матрице тестирования на каждой платформе.
- Поднять минимум позже просто, опустить — нет. Но опускать придётся только при доказанной потребности, которой сейчас нет.
- Для visionOS выбран 1.0, а не 1.1, потому что отличие 1.1 нам не нужно, а платформа всё равно экспериментальная.

Функции более новых ОС используются под `#available`: `excludeDeviceCommunication` (17.4 / 14.4), Controls (iOS 18 / macOS 26), Local Network privacy на macOS (15), виджеты visionOS (26), новый Swift API Network.framework (26).

**Действие:** строку `platforms` в `Package.swift` привести к `[.iOS(.v17), .macOS(.v14), .tvOS(.v17), .visionOS(.v1)]`. Сейчас там iOS 16 и macOS 13.

Сборка для App Store идёт Xcode 26 с SDK 26 — это требование к SDK, на минимумы не влияет.

## 3. Решение: уровни поддержки

| Уровень | Платформы | Что обещаем |
|---|---|---|
| **1 — основные** | iOS, iPadOS, macOS | оба движка (с оговорками ADR-0001 и ADR-0006), полный набор функций платформы, interop-тесты на устройствах перед каждым выпуском |
| **2 — поддерживаемая с ограничениями** | tvOS | туннель и управление; ограниченный набор функций; выпуск не блокируется, если отстаёт от уровня 1 |
| **3 — экспериментальная** | visionOS | Swift-модули компилируются; туннель не обещан до закрытия эксперимента E-6 из ADR-0001 |

### Уровень 1: варианты macOS

Оба варианта упаковки заложены в схему целей с начала:

1. **Developer ID + system extension** — выпускается первым. Не зависит от ревью и от неясных «entitlement restrictions», из-за которых SagerNet ушёл из Mac App Store. Даёт маршрутизацию по процессам, недоступную в App Store-сборке.
2. **Mac App Store + app extension** — вторым. Общий код с iOS; hiddify и OneXray показывают, что вариант жизнеспособен.

Для повседневной разработки удобнее app extension: он не требует активации system extension. Это выбор рабочего процесса, а не порядка выпуска.

Сборка iPad-приложения для Mac («Designed for iPad») не делается: цель macOS нативная.

### Уровень 2: tvOS

Ограничения платформы, не наши [V]: нет `includeAllNetworks`, `excludeLocalNetworks`, `excludeAPNs`, per-app, API для SSID, WidgetKit, ActivityKit, `WKWebView`, `NEDNSSettingsManager`. On-Demand и `enforceRoutes` есть с 17.0.

Следствия:

- правила по SSID внутри движка на tvOS недоступны; только системные On-Demand;
- HTTPS-инспекция на tvOS не предлагается;
- долговечное локальное хранение не предполагается;
- лимит памяти расширения неизвестен — движок заявляется на tvOS только после измерений (ADR-0001, E-4).

Оба движка имеют путь сборки под tvOS: libbox — штатно, Xray — только через c-archive. [V]

### Уровень 3: visionOS

Различия платформ выражаются декларативной моделью возможностей, а не `#if` по всему коду. Поэтому поддержка visionOS на уровне Swift стоит мало, и цель остаётся в манифесте.

Туннеля нет, пока не собран хотя бы один движок. Варианты, в порядке проверки:

1. c-archive моста Xray под SDK `xros`;
2. запуск iPad-сборки в режиме совместимости. В App Store sing-box MT и OneXray показаны доступными на Vision Pro, но у расширений sing-box-for-apple совместимость выключена в проекте; работает ли там туннель — неизвестно;
3. снять visionOS из целей, если оба пути закрыты.

## 4. Последствия

- Одна ветка API на iOS и tvOS; меньше условного кода.
- Пользователи iOS 15–16 и macOS 12–13 не поддерживаются, хотя движки под них собираются.
- tvOS и visionOS не задерживают выпуски уровня 1.
- Заявления о поддержке протоколов действуют по платформам отдельно (`PROTOCOL_MATRIX.md` §7).

## 5. Что не доказано

| Вопрос | Влияние | Как закрыть |
|---|---|---|
| Минимальная ОС для Go 1.27 на darwin и ios | может поднять минимум macOS | release notes Go; запуск моста на macOS 14.0 и iOS 17.0 |
| Лимит памяти расширения на tvOS и visionOS | определяет, какие движки заявлять | измерение на устройстве |
| Сборка Go под visionOS и работа туннеля там | судьба уровня 3 | ADR-0001, E-6 |
| Причина ухода SFM из Mac App Store | риск для варианта MAS | выяснить у upstream; пробная отправка на ревью |
| Per-app правила на неуправляемом macOS | функция уровня 1 | тест на Mac |
| Доля iOS 16 среди целевой аудитории | пересмотр минимума | собственная статистика после запуска |
