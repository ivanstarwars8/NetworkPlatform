# THREAT_MODEL — модель угроз, версия 1

Дата: 2026-11-24. Основание: ADR-0001…0003, `TECHNICAL_RISKS.md`, `PLATFORM_MATRIX.md`, `Documentation/Research/reference-apps.md`.

**Ограничение версии.** Модель описывает намеченную архитектуру. Рабочего приложения нет, поэтому ни одна мера ниже не проверена на устройстве. В столбце «Состояние» стоит: *правило* — записано в ADR, кода нет; *написано* — есть код, который не собирался; *проверено* — подтверждено тестом. Значения «проверено» в этой версии нет ни у одной строки.

## 1. Что защищаем

| № | Актив | Где находится |
|---|---|---|
| A1 | Секреты профиля: UUID, ключи, пароли, токены и адреса подписок | Keychain; в открытом виде — в скомпилированном конфиге и его снимке |
| A2 | Трафик пользователя и DNS-запросы | память процесса расширения |
| A3 | Метаданные: адреса серверов, список профилей, счётчики, журнал | хранилище приложения, журнал расширения |
| A4 | Целостность маршрутизации: трафик идёт туда, куда настроил пользователь | конфиг движка, сетевые настройки туннеля |
| A5 | Доступность: туннель либо работает, либо снят | расширение |
| A6 | Целостность поставки: движки, тулчейн, сборка | сборочная машина, репозиторий |

## 2. Границы доверия

```
подписка, ссылка, QR, файл  ──►  приложение (Swift, без Go)  ──►  Keychain
          недоверенный вход              │
                                         │ startVPNTunnel(options:), sendProviderMessage
                                         ▼
                              расширение Packet Tunnel
                              Swift-хост  │  Go-движок (один)
                                         │
                                         ▼
                              utun ◄──► сеть ◄──► сервер пользователя
```

1. **Внешние данные → приложение.** Всё импортируемое недоверенно.
2. **Приложение ↔ расширение.** Разные процессы; канал предоставляет система.
3. **Swift-хост ↔ движок.** Один процесс, одна память: границы безопасности нет, есть только граница интерфейса.
4. **Устройство ↔ сеть.** Сеть недоверенна; сервер доверен пользователем, но не проектом.
5. **Другие процессы устройства ↔ расширение.** Любой локальный листенер виден им.
6. **Исходники ↔ бинарник.** Сборочная цепочка.

## 3. Нарушители

| Нарушитель | Возможности |
|---|---|
| Наблюдатель в сети | читает и изменяет трафик между устройством и сервером, блокирует его |
| Поставщик подписки | управляет содержимым подписки и её заголовками, видит запросы на обновление |
| Автор ссылки, QR-кода, файла конфигурации | подсовывает произвольные данные для импорта |
| Другое приложение на устройстве | работает в своей песочнице; может обращаться к loopback |
| Устройство в той же локальной сети | обращается к открытым портам устройства |
| Владелец резервной копии или изъятого устройства | читает файлы согласно их классу защиты |
| Участник цепочки поставки | подменяет зависимость, тег, бинарник |

Вне модели: нарушитель с правами ядра или jailbreak; оператор сервера, выбранного пользователем (он видит трафик по определению); принуждение пользователя.

## 4. Угрозы и меры

### 4.1. Импорт и недоверенные данные

| № | Угроза | Мера | Состояние |
|---|---|---|---|
| T-01 | Отказ в обслуживании огромной или вложенной подпиской | ограничения размера и числа элементов на входе импортёра | написано: `ImportLimits` в `ConfigurationEngine`, не собиралось |
| T-02 | Катастрофический перебор в регулярном выражении правила | собственный сопоставитель с линейным временем вместо общего движка регулярных выражений | написано: `LinearRegex` в `RoutingEngine`, не собиралось |
| T-03 | Подписка молча отключает проверку сертификата или меняет маскировку | изменение, влияющее на безопасность, — в отчёте не ниже предупреждения; пользователь видит отчёт до подключения (ADR-0002 §6) | правило; отчёт импорта написан |
| T-04 | Подписка переопределяет настройки приложения | параметры провайдера — только рекомендации с отказом (ADR-0002 §7) | правило |
| T-05 | Профиль «как есть» с произвольным конфигом движка открывает листенер или API | структурная проверка; пометка «не проверяется моделью»; привязка к движку (ADR-0002 §4) | правило |
| T-06 | Утечка через запрос подписки (отпечаток клиента, обращение мимо туннеля) | явный настраиваемый `User-Agent`; путь запроса определяется и показывается | правило; не спроектировано |

### 4.2. Секреты

| № | Угроза | Мера | Состояние |
|---|---|---|---|
| T-10 | Секрет в файле профиля, резервной копии, синхронизации | модель хранит ссылку на секрет, значение — в Keychain | написано: `SecretReference` в `DomainModels`; хранилища нет |
| T-11 | Снимок конфигурации с секретами читается с изъятого устройства | снимок в контейнере расширения, класс защиты файла задан явно | написано, не собиралось; выбор класса не проверен против On-Demand до первой разблокировки (R-14) |
| T-12 | Секреты в журнале, диагностике, тексте ошибки | санирование до записи; ошибки движка обрезаются по длине; конфиг не логируется | частично написано: `CoreError` ограничивает длину сообщений; санирования нет |
| T-13 | Секреты в отчёте о сбое | собственного сборщика нет; в сообщения паник и утверждений секреты не подставляются | правило |
| T-14 | System extension на macOS не может или, наоборот, может слишком многое прочитать из Keychain | расширение Keychain не читает вовсе (ADR-0003 §4) | правило; доступ не проверялся (R-16) |

**Принятый остаточный риск.** Движку нужен конфиг с секретами в открытом виде. Он есть в памяти расширения, в стартовых опциях и в снимке. Защита снимка — только класс защиты файла и песочница.

## 5. Вне этой версии

Функции, которых нет и для которых модель будет дополнена до начала работ: HTTPS-инспекция и управление сертификатами, скрипты и модули, локальный прокси-сервер, Management API, синхронизация и сопряжение устройств. Для сопряжения требование уже записано: канал с аутентификацией и шифрованием, локальный сервер только на время сопряжения (ADR-0003 §3.5).

## 6. Открытые вопросы

1. Достаточна ли системная привязка `sendProviderMessage` как аутентификация (T-21).
2. Какой класс защиты файла снимка совместим с On-Demand после перезагрузки (T-11).
3. Что из Keychain и контейнера группы доступно system extension на macOS (T-14).
4. Каким путём идут запросы подписок при поднятом и снятом туннеле (T-06).
5. Поведение DNS при смене сети (T-33).
6. Как санировать журнал движка, формат которого мы не контролируем (T-12).

## 7. Пересмотр

Модель пересматривается: при появлении первого рабочего туннеля; при добавлении каждого движка; перед началом любой функции из раздела 5; перед выпуском.
