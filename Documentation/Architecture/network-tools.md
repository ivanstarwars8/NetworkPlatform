# Проверки сети и анализатор (уровень Профи)

Дата: 2026-11-27. Код: `Packages/NetworkToolbox` (логика, тесты на Linux), `Apps/SharedApp/Features/Toolbox` и `Apps/SharedApp/Features/Analyzer` (экраны), запрос `.connections` канала приложение–расширение (`Extensions/PacketTunnel/Shared/TunnelMessages.swift`), функция `npb_connections` обоих мостов.

Состояние: логика пакета и функция моста Mihomo проверены тестами на Linux; экраны и `HTTPSProbe` собраны только на macOS CI без подписи (если CI зелёный) и на устройстве не запускались.

## 1. Правила

- Ничего не стоит на пути пакетов. Проверки — сокеты самого приложения; анализатор только читает счётчики движка через `sendProviderMessage`.
- Каждая проверка запускается кнопкой, один раз, с пределом времени и байтов (`ProbeLimits`, `HTTPProbeLimits`, `DNSMessage.maximumMessageBytes`, `PublicAddressService.maximumBytes`). Фоновых циклов нет.
- Анализатор опрашивает расширение раз в секунду, только пока экран открыт, приложение активно и туннель подключён (`.task(id:)`). События (состояние туннеля, ошибки, смена сети) приходят сами: публикации `TunnelController` и обратные вызовы `NWPathMonitor`.
- История ограничена: 300 точек графика (5 минут), 200 событий, 100 закрытых соединений, 50 соединений в одном ответе расширения. Кнопка «Очистить историю» удаляет всё.
- Числа только измеренные. Фаза, которой не было (повторно использованное соединение), показывается как «не измерялось».
- Сторонние сервисы — только с согласия и под своим именем: внешний адрес спрашивается у Cloudflare (`https://1.1.1.1/cdn-cgi/trace`, `https://[2606:4700:4700::1111]/cdn-cgi/trace`) лишь после включения переключателя «Спрашивать у Cloudflare» (по умолчанию выключен). Проверка утечки DNS сторонних сервисов не использует.
- Пока туннель подключён, проверки идут через него (полный туннель); экран об этом говорит.

## 2. Проверки

| Проверка | Как меряется | Ограничения платформы и метода |
|---|---|---|
| Пинг TCP | неблокирующий `connect` + `poll`, время до установленного соединения; имя один раз через `getaddrinfo` | ICMP приложению недоступен; данные не отправляются; до 20 попыток по ≤ 10 с |
| Проверка порта | одна попытка `connect`: открыт / отказ / нет ответа | «нет ответа» не отличает фильтр от недоступного узла; UDP так не проверить |
| Запрос DNS | свой кодек DNS (RFC 1035/3596), UDP на порт 53 выбранного резолвера: системный (`getaddrinfo`), резолвер туннеля, Cloudflare, Google, Яндекс, Quad9 или свой IP | без EDNS и TCP (обрезанный ответ помечается); кириллические имена — через Punycode; DoH/DoT не проверяются |
| Время HTTPS-запроса | `URLSessionTaskMetrics` одного GET в новом эфемерном сеансе → `HTTPPhases` (DNS, TCP, TLS, ожидание ответа, всего) | только `https://`; тело до 64 КиБ, ожидание до 15 с |
| Сертификат TLS | цепочка из проверки доверия сервера, разбор DER (`CertificateParser`: имена, сроки, ключ, подпись, SHA-256), доверие — `SecTrustEvaluateWithError` | разбор для показа, не для решения о доверии |
| Адреса и IPv6 | `getifaddrs`, `NWPathMonitor` (`supportsIPv4/IPv6`); внешний адрес — по согласию (выше) | «есть IPv6» — маршрут есть, а не «сайт ответит» |
| Утечка DNS | `DNSPathCheck`: резолверы системы (`res_ninit`/`res_getservers`, цель `CNetworkToolbox`) против резолверов туннеля (`TunnelAddressing`) + один запрос прямо резолверу туннеля | видна системная настройка, а не DNS отдельных приложений (свой DoH обходит систему); что `res_ninit` в приложении iOS при поднятом туннеле отдаёт резолвер туннеля — не проверено [U] |

## 3. Анализатор

- График: `RateSampler` превращает накопленные счётчики `.statistics` в скорость; сброс счётчиков или пауза больше 5 с начинают заново, а не рисуют выдуманный наклон; разрыв в выборке разрывает линию.
- Выходы: `TunnelTrafficReport.outbounds` (новое необязательное поле, до 64 записей) из `CoreStatistics.outbounds`. Xray считает по выходам, Mihomo — нет (экран так и говорит).
- Соединения: `TunnelTrafficReport.activeConnections` (Mihomo) и список `.connections` → `CoreLifecycle.connections(limit:)` → `MihomoCore` → `npb_connections` (трекер ядра `statistic.DefaultManager`). Xray списка соединений в процессе не ведёт: `npb_connections` моста Xray отвечает кодом 5, адаптер `XrayCore` — `unsupportedFeature(.connectionList)`, мост даже не спрашивается. «Недавно закрытые» — соединения, исчезнувшие между двумя опросами, пока экран открыт (`ConnectionTracker`).
- Адреса назначения соединений — данные пользователя: показываются на экране, не пишутся в журнал ни приложением, ни расширением и не попадают в диагностику.
- Предел ответа: 50 соединений, строки до 200 байт, теги и цепочка до 64 байт × 4 — самый большой ответ меньше 64 КиБ канала (тест `testConnectionReportRoundTripAndBounds`).

## 4. Диагностика для отправки

`DiagnosticsBundleBuilder` собирает текст по кнопке «Собрать диагностику» (не на каждом обновлении экрана): версии приложения и системы, состояние туннеля и движка, счётчики, выходы под нейтральными именами («выход 1», …), события. Всё проходит `DiagnosticsRedactor`: URL, почта, пары `ключ=значение` с секретами, UUID, IPv4/IPv6 (время вида `22:51:09` не трогается), имена узлов (латиница, кириллица, `xn--`), длинные строки base64/hex с цифрами. Профили, адреса серверов, список соединений и результаты проверок не читаются вовсе. Текст виден до отправки; отправка — системный лист «Поделиться» (на Apple TV его нет).

## 5. Права и настройки приложения

- macOS: `com.apple.security.network.client` в `App-macOS.entitlements` (исходящие соединения проверок); слушающих сокетов нет.
- iOS: `NSLocalNetworkUsageDescription` — проверка адреса локальной сети вызывает системный запрос.
- ATS: проверяются только `https://`, исключений ATS нет.

## 6. Не проверено

- Ничего из экранов не запускалось на устройстве: вид, VoiceOver, Dynamic Type, поведение `URLSessionTaskMetrics` (порядок вызова `didFinishCollecting` и `didCompleteWithError` [U]), запрос локальной сети, `res_ninit` на iOS, `NWPathMonitor` при смене сети.
- Список соединений Mihomo проверен в мосту на Linux (`TestConnectionsList`); путь через расширение — только тестами Swift против поддельного моста.
