# Правила маршрутов и DNS: от настроек до движка

Дата: 2026-11-27. Код: `Packages/RoutingPolicy` (модель настроек, проверка ввода, разбор списков, таблица, объяснения), `Packages/ConfigurationEngine` (`XrayRuleCompiler`, DNS в обоих компиляторах, встроенные rule-providers Mihomo), `Apps/SharedApp/Features/Routing` (экраны «Правила», «DNS», «Маршрут»), `Apps/SharedApp/RoutingSettingsModel.swift`.

Пометки: **[V]** — проверено запуском (указано чем); **[U]** — не проверено.

## 1. Путь

```
RoutingSettings (routing.json)  ──RoutingPolicyCompiler──▶  RoutingTable  ──RuleLowering──▶  XrayRuleCompiler  ─▶ routing.rules (Xray JSON)
  основа, свои правила,              + происхождение              │                    MihomoRuleCompiler ─▶ rules + rule-providers (YAML)
  списки (rulesets/<id>.json),         каждого правила            │
  DNS                                                             └──RouteSimulator──▶ RouteExplainer ─▶ экран «Маршрут»
```

- Источник истины один — `RoutingTable`, построенная из настроек для выбранного профиля. Движки получают её через `RuleLowering`, симулятор отвечает по ней же (`routing-parity.md`). Таблица, которую нельзя передать движку без потерь, — ошибка подключения с текстом, а не тихое приближение.
- Порядок: свои правила (сверху вниз), списки по ссылке, встроенные списки основы, затем итог основы (`Всё через VPN` и `Российские сайты напрямую` — через VPN, `Только заблокированное` — напрямую).
- «Через VPN» — выбранный сервер или группа профиля (`RoutingPolicyCompiler.tunnelAction`). В Xray это главный маршрут компилятора (исходящий или балансировщик); в Mihomo — имя прокси или группы.
- `domainStrategy` всегда `asIs`: маршрутизатор сам не разрешает имена, лишних запросов DNS на соединение нет. Адресные правила видят адрес соединения.
- «Всё через VPN» без своих правил и списков движкам таблицу не передаёт: вывод компиляторов такой же, как до появления правил.
- Счётчики срабатываний правил не показываются: движки отдают их только через свои API статистики, а их опрос — фоновая работа в расширении.

## 2. Как правило попадает в движок

- **Xray.** Каждое плоское правило — поле `rules` с `ruleTag` `r<номер>.<часть>` (тот же тег показывает «Маршрут»). Домены `full:`/`domain:`/`keyword:`, адреса — `ip`, порты — строка, сеть — `network`. Соединения из туннеля несут только адрес, поэтому при доменных правилах у входящего `tun` включается `sniffing` (`http`, `tls`, `quic`, `routeOnly: true`): имя читается из первого пакета и используется только для выбора маршрута, соединение остаётся на своём адресе.
- **Mihomo.** Одно правило на значение (`DOMAIN-SUFFIX,…`), кроме длинных: плоское правило только из доменов (точных или суффиксов) или только из адресов, от 16 значений, становится `RULE-SET` над встроенным провайдером (`rule-providers`, `type: inline`, `behavior: domain`/`ipcidr`) — ядро сверяет его деревом/множеством диапазонов, а не построчно. Имя домена Mihomo берёт из сопоставления DNS (`redir-host`).
- **Проверка.** `RoutingPolicyCompileTests`: для каждой основы, с правилами всех видов и длинным списком и без них, ответ `RouteExplainer` сравнивается с решением, которое даёт вывод компилятора Xray и вывод компилятора Mihomo (оценщик подмножества правил, которое производит политика), — 6 наборов × 528 запросов на движок, тег правила Xray тоже совпадает **[V, swift test, Linux]**. Тот же вывод принят ядрами: `xray run -test` (Xray 26.11.9) и `mihomo -t` (Mihomo v1.19.34) — 12 конфигураций из `testExportPolicyConfigurations` **[V, сервер разработки, 2026-11-27]**. Поведение в работающем туннеле на устройстве **[U]**.

## 3. Списки по ссылке

- Загружаются только при добавлении и по кнопке «Обновить» (эфемерная сессия, без cookies и кэша), фонового обновления нет. Неудачная загрузка оставляет записи прошлой и показывает причину.
- Форматы: домен или адрес в строке; `full:`/`domain:`; `DOMAIN`, `DOMAIN-SUFFIX`, `IP-CIDR`, `IP-CIDR6`; элементы `payload:`; строки hosts (`0.0.0.0 имя`). `+.`, `*.`, `.` — «имя и поддомены» (`*.` и `.` чуть шире написанного). Ключевые слова, регулярные выражения, процессы пропускаются и считаются.
- Сжатие: суффиксы, покрытые более коротким суффиксом списка, удаляются; точные имена под суффиксом удаляются; сети внутри другой сети списка удаляются.
- Пределы проекта (`RuleSetLimits`): ответ до 2 МиБ, в списке до 10 000 записей после сжатия, во всех включённых вместе до 20 000. Все записи попадают в конфигурацию, которую расширение разбирает в пределах ~50 МиБ памяти; geo-базы не загружаются никогда. Затраты памяти расширения на 20 000 записей не измерены **[U]** — до замера на устройстве это верхняя граница, а не обещание.

## 4. DNS

- Серверы в общей записи компиляторов: адрес (UDP), `tcp://`, `https://` (DoH), `tls://` (DoT). У Xray нет клиента DoT (`app/dns/nameserver.go`): с `tls://` компилятор Xray отказывает с причиной, подключение не начинается; экран DNS предупреждает заранее. Серверы `+local` и `localhost` (мимо туннеля) не принимаются.
- Серверы для доменов: Xray — объект сервера с `domains: ["domain:…"]`, `skipFallback: true`, перед общими; Mihomo — `nameserver-policy` `+.домен`.
- «Адреса IPv6» выключено: Xray `queryStrategy: UseIPv4`, Mihomo `dns.ipv6: false`.
- «Защита от утечек» (по умолчанию включена): все запросы резолвера идут выбранным маршрутом — Xray: правило `inboundTag: dns-internal` → главный маршрут; Mihomo: `#<маршрут>` у каждого сервера. Выключена: запросы резолвера идут по правилам — Xray без этого правила, Mihomo `respect-rules: true` (с обязательным `proxy-server-nameserver`). Перехват порта 53 из туннеля (`dns-hijack`, правило `tun-in` → `dns-out`) от переключателя не зависит.

## 5. Встроенные списки основ

`PresetLists.swift`: короткие, чтобы не раздувать каждую конфигурацию. «Российские сайты напрямую» — зоны `.ru`, `.su`, `.рф`, `.рус`, `.москва`, `.дети` и домены крупных российских сервисов вне этих зон; адресов российских сетей нет (их добавляют списком по ссылке). «Только заблокированное» — домены заблокированных в России и закрытых для российских пользователей сервисов и опубликованные диапазоны адресов Telegram. Состав — выбор проекта; актуальность списков со временем не проверяется.
