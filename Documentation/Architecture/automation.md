# Автоматизация: автоподключение, защита от утечек, быстрые команды

Дата: 2026-11-28. Код: `Packages/TunnelAutomation` (настройки, план правил, состояние автоподключения; Linux-тесты), `Apps/SharedApp/TunnelController.swift` (перенос на `NETunnelProviderManager`), `Apps/SharedApp/Features/Automation/` (экран «Автоподключение», App Intents). Состояние: логика проверена тестами на Linux; приложение собирается на macOS CI без подписи; на устройстве ничего не запускалось.

## 1. Каждый переключатель — одна системная настройка

| Экран | Поле `AutomationSettings` | Системная настройка |
|---|---|---|
| Подключаться автоматически | `connectOnDemand` | `NEVPNManager.isOnDemandEnabled` (через `OnDemandState`, §2) |
| В сетях Wi-Fi / По сотовой сети / По кабелю | `connectOnWiFi` / `connectOnCellular` / `connectOnWired` | `NEOnDemandRuleConnect` или `NEOnDemandRuleIgnore` с `interfaceTypeMatch` `.wiFi` / `.cellular` / `.ethernet` |
| Доверенные сети Wi-Fi | `trustedNetworks` | `NEOnDemandRule.ssidMatch` правила с `.wiFi`, первым в списке |
| Отключать туннель в этих сетях | `disconnectOnTrusted` | то же правило — `NEOnDemandRuleDisconnect` вместо `NEOnDemandRuleIgnore` |
| Весь трафик только через туннель | `includeAllNetworks` | `NEVPNProtocol.includeAllNetworks` |
| Оставить доступ к локальной сети | `excludeLocalNetworks` | `NEVPNProtocol.excludeLocalNetworks` (записывается только вместе с `includeAllNetworks`, иначе `false`) |
| Открывать при входе в систему (Mac) | — | `SMAppService.mainApp.register()` / `unregister()` |

Порядок правил (`OnDemandPlanner`): доверенные сети → по одному правилу на тип сети платформы (Connect или Ignore) → завершающее `Ignore` для любой сети. Ignore не трогает туннель: включённый вручную остаётся, выключенный не поднимается. Правило для типа, которого у платформы нет, не создаётся.

Имена сетей вводятся вручную. Сопоставление `ssidMatch` делает система, приложению для этого разрешения не нужны [U]. Прочитать имя текущей сети (кнопка «добавить эту сеть») приложение не может: для `NEHotspotNetwork.fetchCurrent` нужны entitlement «Access Wi-Fi Information» и разрешение геолокации — их нет в профиле подписи и они не запрашиваются. Проверка имени (`TrustedNetworks`): 1–32 байта UTF-8, без управляющих символов, без повторов, не больше 50; регистр сохраняется.

## 2. Когда автоподключение включается в системе

`OnDemandState` (тесты `OnDemandStateTests`):

- **Нужен снимок.** Система запускает туннель без запроса запуска; расширение стартует со своего снимка последнего успешного запуска (ADR-0008, `ConfigurationSnapshotStore`). Пока не было ни одного успешного подключения вручную, снимка нет, и каждый автоматический запуск падал бы и повторялся. Поэтому `isOnDemandEnabled` ставится только после первого состояния «Подключено» (`hasConnectedOnce`). Новая конфигурация VPN сбрасывает флаг.
- **Профиль автоподключения** — профиль последнего успешного подключения вручную; это написано на экране.
- **Ручное отключение** сначала сохраняет `isOnDemandEnabled = false`, потом `stopVPNTunnel()`; иначе система сразу подняла бы туннель снова. Автоподключение приостановлено (`suspendedByUser`) до следующего подключения вручную.
- **При ручном подключении** автоподключение включается только после «Подключено»: включённое до старта, оно могло бы дать системе запустить старый снимок раньше нового запроса.
- **Выключено снаружи** (переключатель VPN в системных настройках): при чтении конфигурации приложение видит `isOnDemandEnabled = false` там, где ждало `true`, и считает это ручным отключением, а не включает обратно.

Изменения правил и `isOnDemandEnabled` сохраняются сразу. `includeAllNetworks`/`excludeLocalNetworks` сохраняются только при отключённом туннеле (до ручного старта или когда туннель остановился): изменение протокола у работающего туннеля система может применить перезапуском [U]. Пока изменение ждёт, экран пишет «Изменение применится, когда туннель отключится». Сохранения идут строго по одному (`scheduleSync`).

Предупреждения на экране: с `includeAllNetworks` интернет недоступен, пока туннель не работает (в том числе при сбое расширения); без `excludeLocalNetworks` локальные устройства (принтеры, AirPlay) могут не работать; с «Отключать в доверенных сетях» подключиться вручную в такой сети нельзя.

## 3. Быстрые команды (App Intents)

`Features/Automation/TunnelIntents.swift`: «Подключить», «Отключить», «Переключить подключение», «Выбрать профиль» (параметр — `ProfileEntity`: только идентификатор и имя), «Состояние подключения» (возвращает текст). Фразы Siri — у трёх (`BykShortcuts`). Действия выполняются в процессе приложения (`openAppWhenRun = false`) на тех же объектах, что и окна (`Shell/AppModel.swift`), и тем же путём, что кнопка. Результат ждётся по уведомлениям о состоянии (`$status`, без опроса), не дольше 20 с (подключение) / 10 с (отключение); исход сообщается честно: «Подключено», «Не подключилось…», «Состояние ещё меняется».

Ограничения: первое подключение — только в приложении (система спрашивает разрешение VPN, фоновое действие этого показать не может); действие сообщает об этом. «Выбрать профиль» при работающем туннеле переподключает его.

Автоматизации (подключение к Wi-Fi, режим фокусирования, время суток) пользователь собирает в «Быстрых командах» из этих действий; отдельного фильтра фокусирования (`SetFocusFilterIntent`) нет.

## 4. Не сделано и почему

- **Пункт управления (ControlWidget, iOS 18) и виджет на экране «Домой».** Оба требуют отдельной цели расширения WidgetKit с собственным идентификатором бандла, App Group и профилем подписи. Подписанная сборка TestFlight (`testflight.yml`, `Byk.xcconfig`) знает только приложение и расширение туннеля: новое встроенное расширение без зарегистрированного идентификатора и профиля сломало бы её. Нужен шаг владельца: зарегистрировать идентификатор `<app>.widgets` и профиль. До этого с iOS 18 в Пункт управления и на кнопку действия можно поставить быструю команду с действием «Переключить подключение».
- **Чтение имени текущей сети Wi-Fi** — см. §1.
- **Apple TV** — нет экрана настроек (одна панель) и нет «Быстрых команд»: автоподключение, защита от утечек и App Intents на tvOS не собираются.

## 6. Что проверить на устройстве

1. Первое подключение вручную → «Подключено» → в Настройках iOS у VPN включено «Подключать по запросу».
2. Самолётный режим вкл/выкл на сотовой — туннель поднимается сам, со старым профилем.
3. Доверенная сеть с Ignore и с Disconnect.
4. Отключение кнопкой — туннель не поднимается сам; подключение кнопкой — снова поднимается.
5. `includeAllNetworks`: убить расширение (`kill` на Mac) — трафик не идёт мимо туннеля; с `excludeLocalNetworks` принтер в локальной сети доступен.
6. Быстрые команды: все пять действий при закрытом приложении; Siri «Подключить Бык».
7. Mac: запуск при входе, статус `requiresApproval`.
