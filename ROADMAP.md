# ROADMAP

Этапы 0–10 из спецификации владельца (§30) с критериями выхода. Этап закрыт, когда выполнены **все** его критерии и результат записан в `STATUS.md`. Сроков нет: их нельзя оценить, пока не закрыт R-01 (ничего не собрано).

Числовые критерии производительности заданы спецификацией владельца (§26); в репозиторий они ещё не перенесены. Там, где ниже сказано «в пределах критериев», имеются в виду они.

Обозначения экспериментов E-1…E-9 — из ADR-0001 §7; рисков R-xx — из `TECHNICAL_RISKS.md`.

| Этап | Состояние на 2026-11-24 |
|---|---|
| 0. Research | завершён по документам; вопросы владельцу открыты |
| 1. Network Foundation | начат; заблокирован отсутствием Mac, подписи и устройств |
| 2–10 | не начаты |

## Phase 0 — Research

Аудит платформ, лицензий, ядер, SDK и существующих реализаций.

Критерии выхода:

- [x] Аудит sing-box, Xray-core, libXray и четырёх референс-клиентов по исходникам с закреплёнными SHA (`Documentation/Research/`).
- [x] Матрицы протоколов, платформ, конкурентов; аудит лицензий; реестр рисков.
- [x] Решения об интеграции движков, модели конфигурации, IPC, структуре, минимальных ОС записаны в ADR-0001…0005.
- [ ] Ответы владельца на вопросы ADR-0006 §6 (лицензия, CLA, правообладатель, один продукт или два). Блокируют публикацию, но не Phase 1.

Этап считается завершённым по объёму исследования. Всё, что требует сборки или устройства, перенесено в Phase 1 как эксперименты.

## Phase 1 — Network Foundation

Рабочий Packet Tunnel, базовое ядро, управление жизненным циклом, конфигурация и тестовый сервер.

Предпосылки (сейчас отсутствуют): Mac с Xcode; аккаунт Apple Developer с возможностью Network Extension; iPhone; тестовый сервер.

Критерии выхода:

- [ ] `swift build` и `swift test` проходят на macOS и Linux; результат записан.
- [ ] Мост Xray собран как XCFramework из закреплённых версий; процедура воспроизводима (E-1).
- [ ] Приложение и расширение собираются из репозитория по документированным шагам.
- [ ] utun fd получается на всех поддерживаемых версиях iOS (E-5).
- [ ] На физическом iPhone туннель пропускает TCP, UDP и DNS через один узел тестового сервера (E-1).
- [ ] Профиль проходит путь: ссылка → модель → скомпилированный конфиг с отчётом → запуск.
- [ ] Отказ движка снимает туннель; серия быстрых start/stop не оставляет туннель без движка (E-9).
- [ ] Измерен пиковый `phys_footprint` расширения под нагрузкой хотя бы на одном устройстве (начало E-4).
- [ ] Отчёт о лицензиях транзитивных Go-зависимостей моста (R-18).

## Phase 2 — Production Stability

Смена сети, восстановление, DNS, память, нагрузочные тесты.

Критерии выхода:

- [ ] Смена Wi-Fi ↔ сотовая сеть, сон и пробуждение, потеря и возврат сети: туннель восстанавливается или снимается, трафик не теряется молча (R-13).
- [ ] On-Demand: запуск системой из снимка конфигурации, в том числе после перезагрузки; поведение до первой разблокировки задокументировано (R-14, ADR-0003 §7).
- [ ] Поведение DNS определено и проверено на утечки.
- [ ] Таблица памяти: устройство × ОС × движок × нагрузка; расширение не завершается по памяти на самом старом поддерживаемом iPhone (E-4, R-03).
- [ ] Длительный прогон и нагрузочные тесты в пределах критериев.
- [ ] Замерены пределы `sendProviderMessage` и `options` у `startVPNTunnel` (R-17).

## Phase 3 — Professional Routing

Правила, группы, подписки, наборы правил, DNS engine, симулятор маршрутов.

Критерии выхода:

- [ ] Правила маршрутизации компилируются в конфиг движка; решение симулятора совпадает с поведением движка на наборе эталонных запросов.
- [ ] Группы узлов и переключение узла без пересоздания VPN-конфигурации.
- [ ] Подписки: загрузка, обновление, заголовки `subscription-userinfo` и другие из ADR-0002 §7; ограничения размера; параметры провайдера не применяются без согласия.
- [ ] Наборы правил с известной лицензией источника (ADR-0006 §6, вопрос 10).
- [ ] Эталонные пары «вход → конфиг → отчёт» для каждого импортируемого формата (R-11).

## Phase 4 — Adaptive Intelligence

Проверки работоспособности, балансировка, автоматический выбор сервера, диагностика качества.

Критерии выхода:

- [ ] Способ замера задержки до подключения выбран и сопоставлен с задержкой через движок (R-15).
- [ ] Автоматический выбор и переключение узла при отказе; время восстановления в пределах критериев.
- [ ] Проверки не расходуют батарею в фоне сверх критериев.
- [ ] Диагностический пакет собирается одним действием, санирован и показан пользователю до отправки.

## Phase 5 — Multi-Core

Второе ядро, матрица возможностей, компилятор конфигурации, переключение движков.

Критерии выхода:

- [ ] libbox собран цепочкой upstream из закреплённых версий; линия (1.14.x или 1.15) выбрана после сверки тегов (E-2, R-07, R-09).
- [ ] Решён вопрос двух расширений в одном приложении (E-3) либо зафиксирован вариант «два приложения».
- [ ] Компиляторы под оба движка; таблица возможностей закреплена за версией движка.
- [ ] Interop-тесты по `PROTOCOL_MATRIX.md` §7 для заявленных сочетаний.
- [ ] Смена движка — остановка и запуск без вмешательства пользователя в Настройках.
- [ ] Решение владельца по sing-box в App Store (ADR-0006 §6, вопрос 5).

## Phase 6 — Multi-Platform

macOS, iPadOS, tvOS, visionOS и платформенные адаптеры.

Критерии выхода:

- [ ] macOS: вариант Developer ID с system extension и вариант Mac App Store с app extension; проверен доступ system extension к keychain и контейнеру группы (R-16).
- [ ] iPadOS: интерфейс под большой экран.
- [ ] tvOS: туннель и управление; измерен лимит памяти; проверена сохранность снимка конфигурации (R-17).
- [ ] visionOS: закрыт E-6 — либо туннель работает, либо платформа снята из целей с записью в ADR-0005.
- [ ] Минимальные версии ОС подтверждены запуском (E-8, R-20).

## Phase 7 — Professional Tools

Network Analyzer, Network Toolbox, цепочки прокси, локальный прокси, Configuration Studio.

Критерии выхода:

- [ ] Каждый инструмент проверен в реальном сценарии и не увеличивает память расширения сверх бюджета из Phase 2.
- [ ] Локальный прокси: отдельный ADR с учётом TN3120 (R-10); листенер защищён и выключен по умолчанию.
- [ ] Цепочки: поддерживаемые сочетания перечислены и покрыты interop-тестами.

## Phase 8 — Extensibility

Модули, автоматизация, скрипты, HTTPS-инспекция.

Критерии выхода:

- [ ] Отдельное исследование и ADR до начала работ (R-22).
- [ ] Декларативные модули раньше скриптов; API скриптов узкий; скрипты в расширении — только после измерений памяти.
- [ ] HTTPS-инспекция под флагом сборки; на tvOS не предлагается; модель угроз дополнена.
- [ ] Сборка с этими функциями прошла ревью хотя бы в TestFlight.

## Phase 9 — Ecosystem

Синхронизация устройств, Management API, интеграция с панелями и пользовательскими серверами.

Критерии выхода:

- [ ] Сопряжение устройств по каналу с аутентификацией и шифрованием; локальный сервер только на время сопряжения (ADR-0003 §3.5).
- [ ] Management API: аутентификация, выключен по умолчанию, модель угроз дополнена.
- [ ] Интеграции с панелями описаны как контракты и покрыты тестами.

## Phase 10 — Release

Аудит безопасности, производительности, лицензий, соответствия App Store и документации.

Критерии выхода:

- [ ] Лицензия выбрана; `LICENSE`, `THIRD_PARTY_NOTICES.md` и SBOM соответствуют фактическому составу сборки.
- [ ] Аккаунт-организация с выданной возможностью Network Extension (R-02); экран раскрытия данных — до первого использования (Guideline 5.4).
- [ ] Независимый или внутренний аудит безопасности; модель угроз актуальна.
- [ ] Все критерии производительности выполнены на физических устройствах.
- [ ] Две независимые сборки из одного набора SHA сопоставлены; расхождения из-за подписи Apple задокументированы (R-19).
- [ ] Руководство пользователя, инструкции сборки, политика раскрытия уязвимостей с рабочим каналом связи.
- [ ] Публикация — только по решению владельца.
