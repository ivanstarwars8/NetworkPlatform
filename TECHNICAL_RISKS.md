# TECHNICAL_RISKS — реестр рисков

Дата проверки: **2026-11-24**. Основание — `RESEARCH.md` и первичные документы, на которые он ссылается.

Шкалы:

- **Вероятность**: высокая — ожидаем, что случится без специальных мер; средняя — есть конкретные признаки; низкая — возможно, признаков нет.
- **Ущерб**: критический — проект или платформа не выходит; высокий — теряется движок, канал распространения или месяцы работы; средний — теряется функция или недели; низкий — неудобство.
- Риски упорядочены по произведению вероятности и ущерба, при равенстве — по тому, насколько рано риск блокирует работу.

Оценки вероятности — суждение архитектора по прочитанным документам, не измерение.

## R-01. Ничего не собрано

**Суть.** Все пять аудитов сделаны на Linux-хосте без Go, Xcode и Swift. Ни libbox, ни мост Xray, ни Swift-пакет не собирались. Архитектура опирается на чтение кода.

**Смягчение.** Первая задача после документов — Mac-сборщик и минимальный вертикальный срез: мост Xray → XCFramework → расширение → туннель на одном iPhone. До этого не писать адаптеры «вглубь».

**Что закроет.** Журнал воспроизводимой сборки обоих XCFramework из закреплённых версий и туннель, пропускающий трафик на реальном устройстве.

## R-02. Организационные предпосылки

**Суть.** Guideline 5.4: VPN-приложения публикует только аккаунт-организация. DPLA 3.3.3(G): entitlement Network Extension выдаёт Apple и может отозвать. `wifi-info` и `multicast` — по отдельному запросу. Территории с лицензированием VPN требуют лицензии или исключения из доступности.

**Смягчение.** Зарегистрировать юрлицо и аккаунт до начала работ, требующих подписи. Экран раскрытия данных — первый экран онбординга. Не закладывать `multicast` в базовую функциональность.

**Что закроет.** Действующий аккаунт-организация с выданной capability Network Extension для iOS, tvOS, visionOS, macOS (включая Developer ID).

## R-03. Память расширения

**Суть.** Официального лимита нет. 50 МиБ — пост DTS и константа в sing-box. Для tvOS, visionOS и старых iPhone чисел нет вообще. Потребление ни одного движка в расширении не измерено. sing-box рассчитывает на мягкий лимит 40 МиБ, libXray — на 30 МиБ с GC 10 %. Swift-обвязка, логирование и будущий скриптовый движок делят тот же бюджет.

**Смягчение.** Один движок на процесс (ADR-0001). Параметры GC и лимита задаёт наш мост, а не зашитые значения upstream. Сокращённый набор тегов sing-box. Телеметрия `phys_footprint` в расширении с первого дня. Скрипты в расширении — только после измерений.

**Что закроет.** Таблица: устройство × ОС × движок × нагрузка → пиковый `phys_footprint` и факт завершения по памяти. Минимум: самый старый поддерживаемый iPhone, Apple TV, Vision Pro.

## R-04. GPLv3 и App Store

**Суть.** sing-box и все `sing-*` — GPL-3.0-or-later. Исключения для App Store нет, CLA нет, письменного разрешения третьим лицам в исходниках нет. Karing и Hiddify публикуют производные без видимого разрешения. Риск — удаление по жалобе любого правообладателя, а не отказ на ревью.

**Смягчение.** Архитектура допускает сборку без sing-box (ADR-0001, вариант `XrayOnly`). Адаптер sing-box изолирован в отдельном модуле (ADR-0004). Решение о публикации sing-box-сборки в App Store — за владельцем (ADR-0006).

**Что закроет.** Письменное разрешение SagerNet, либо решение владельца принять риск, либо решение не публиковать sing-box-сборку в App Store. Плюс заключение юриста по GPLv3 §6 и §10.

## R-05. Два расширения в одном приложении

**Суть.** ADR-0001 выбирает расширение по `providerBundleIdentifier`. Допустимость двух packet-tunnel-расширений в одном iOS-приложении, поведение `NETunnelProviderManager` и отношение ревью не проверены. Ни один референс так не делает.

**Смягчение.** Control plane не знает, сколько расширений в бандле: он работает со списком установленных движков. Запасной вариант — два варианта приложения с одним расширением каждый; он же нужен по лицензионным причинам.

**Что закроет.** Тестовое приложение с двумя расширениями на iPhone и Apple TV: установка, переключение, On-Demand, поведение после перезагрузки. Затем — прохождение TestFlight-ревью.

## R-06. visionOS

**Суть.** В форке gomobile нет целей `visionos`/`xros`; в скриптах libXray их тоже нет; cronet-срезов нет. Поддерживает ли Go сборку под visionOS — не проверялось. У sing-box-for-apple расширения не разрешены в режиме совместимости с iPad, хотя в App Store приложение показано доступным на Vision Pro.

**Смягчение.** visionOS — экспериментальный уровень (ADR-0005): Swift-модули компилируются, туннель не обещан. Мост Xray на c-archive не зависит от gomobile, поэтому пробовать его первым.

**Что закроет.** C-архив моста Xray, собранный под SDK `xros` и слинкованный в расширение, которое поднимает туннель на Vision Pro. Либо доказанная невозможность — тогда visionOS снимается из целей.

## R-07. Хрупкость тулчейна sing-box

**Суть.** 62 `go:linkname`, `-checklinkname=0`, теги `badlinkname` и `tfogo_checklinkname0`, обязательные `-X runtime.godebugDefault=…`, патч `GOROOT/src/internal/cpu` для iOS и tvOS, форк gomobile с расхождением v0.1.12 / v0.1.13 между `go.mod` и `Makefile`. Обновление Go может сломать сборку или рантайм.

**Смягчение.** Закрепить Go, gomobile и SHA sing-box в одном файле сборки. Воспроизводить CI upstream, а не изобретать свою цепочку. Обновлять движок только вместе с прогоном interop-тестов. Не пытаться собрать sing-box на Go, которым upstream его не собирает.

**Что закроет.** Сборка libbox на нашем Mac из закреплённых версий, совпадающая по набору срезов с upstream, и документированная процедура обновления, пройденная хотя бы один раз.

## R-08. Получение utun fd

**Суть.** Публичного API для fd у `NEPacketTunnelProvider` нет. Оба известных приёма недокументированы: KVC `packetFlow.socket.fileDescriptor` (приватный ключ) и перебор fd с `getpeername` (публичные вызовы, приём WireGuard). Оба Go-движка читают utun напрямую и без fd не работают. Guideline 2.5.1 требует публичных API.

**Смягчение.** Перебор fd — основной путь, KVC — запасной под флагом сборки. Код в одном файле адаптера, с проверкой на старте и понятной ошибкой. Тест на каждой бета-версии ОС.

**Что закроет.** Закрыть полностью нельзя: это зависимость от поведения ОС. Снижает — успешный тест на всех поддерживаемых версиях каждой платформы и прохождение ревью.

## R-09. Нестабильность API движков

**Суть.** `PlatformInterface` libbox — около 30 методов, растёт с фичами upstream; новая сигнатура ломает компиляцию Swift-адаптера. Аудит сделан по альфа-ветке; отличия от 1.14.x неизвестны. README libXray прямо не гарантирует стабильность API.

**Смягчение.** Типы `Libbox*` и JSON-конверт libXray не выходят за пределы адаптеров. Версия движка закреплена. Для Xray — собственный мост с нашим C ABI, который меняем мы.

**Что закроет.** Решение, какую линию sing-box закрепляем (после сверки тегов), и одно выполненное обновление каждого движка с измеренной стоимостью.

## R-10. TN3120

**Суть.** Apple называет неподдерживаемыми в packet tunnel фильтрацию, перехват всего DNS, выборочную маршрутизацию и локальные листенеры. Вся категория продуктов построена на этом. Риск — поломка в новой версии ОС без помощи DTS.

**Смягчение.** Альтернативы для потребителя на iOS, tvOS, visionOS нет. Не добавлять листенеров сверх необходимого движку (ADR-0003). На macOS оставить в абстракции место для `NETransparentProxyProvider`.

**Что закроет.** Не закрывается. Отслеживать бета-версии ОС.

## R-11. Потери при конвертации

**Суть.** Наборы протоколов движков различаются (`PROTOCOL_MATRIX.md` §6). Xray 26.11.9 игнорирует `header`/`seed` у mKCP — старые ссылки молча теряют маскировку. `downloadSettings` XHTTP рекурсивен и не укладывается в плоскую модель.

**Смягчение.** ADR-0002: компилятор возвращает отчёт о потерях; профиль с неустранимыми потерями не запускается молча. Импортёр мигрирует mKCP в `finalmask.udp` и сообщает об этом.

**Что закроет.** Набор эталонных пар «вход → конфиг движка → отчёт» в тестах для каждого импортируемого формата и interop-тесты по `PROTOCOL_MATRIX.md` §7.

## R-12. Собственный Go-мост для Xray

**Суть.** В `Invoke` libXray нет потоков статистики и логов, тюнинг памяти зашит, версии в сборке upstream не закреплены. Нужен свой мост — значит, проект поддерживает Go-код и сборку c-archive под каждую платформу.

**Смягчение.** Мост минимален: запуск с конфигом и fd, остановка, состояние, статистика, лог. Разбор ссылок из `share/` libXray (MIT) не переносить в мост — импорт делает Swift.

**Что закроет.** Работающий мост с тестом жизненного цикла и измеренной стоимостью обновления Xray-core на одну версию.

## R-13. Отказ движка и остановка

**Суть.** hiddify исправлял баг: туннель оставался поднятым без ядра и забирал весь трафик. OneXray при сбое `stopXray` завершает процесс через `exit(0)`. Чистая остановка Go-ядра внутри живого процесса не гарантирована.

**Смягчение.** Сторож: движок остановился сам → `cancelTunnelWithError`. Счётчик поколений для гонок start/stop. Вызовы движка — на выделенном исполнителе. Завершение процесса — только аварийный путь после тайм-аута.

**Что закроет.** Тесты на устройстве: убить движок изнутри, быстрые start/stop, смена сети, сон и пробуждение — туннель снимается или восстанавливается, трафик не «чернеет».

## R-14. Секреты

**Суть.** Конфиг движка содержит UUID, ключи, пароли. Upstream передаёт его строкой в стартовых опциях и сохраняет снимок на диск для запусков системой. Защита этого снимка в первичных документах не описана.

**Смягчение.** ADR-0003: снимок хранит расширение, класс защиты файла задан явно; в журнал и диагностический пакет конфиг попадает только санированным.

**Что закроет.** Проверка на устройстве: снимок читается при On-Demand после перезагрузки до первой разблокировки (или документированный отказ), и модель угроз для снимка.

## R-15. Проверка до подключения

**Суть.** Приложение не линкует Go (ADR-0001), значит, нет `LibboxCheckConfig` и `testXray` в приложении. `pingBatch` и `testXray` libXray запрещены при работающем ядре. Замер задержки до подключения без второго экземпляра движка — открытый вопрос всех аудитов.

**Смягчение.** Проверка схемы и семантики — в Swift-компиляторе. Задержка до подключения — нативный TCP/TLS-пробник на Swift как минимальный вариант. Режим расширения «только проверка» — отдельное исследование.

**Что закроет.** Прототип пробника с оценкой, насколько его результат соответствует задержке через движок, и решение по режиму «проверка».

## R-16. Варианты macOS

**Суть.** SagerNet ушёл из Mac App Store из-за неназванных «entitlement restrictions», при этом hiddify и OneXray там есть. Доступ system extension к пользовательскому keychain и контейнеру App Group не документирован. SSID на macOS, вероятно, требует геолокации.

**Смягчение.** Оба варианта macOS в схеме целей с начала. Секреты в system extension передаются сообщением или опциями, а не читаются из keychain. Первым выпускается вариант Developer ID.

**Что закроет.** Тест на Mac: system extension читает и не читает keychain и контейнер; выяснение причины ухода SFM из MAS.

## R-17. IPC и хранение на tvOS

**Суть.** Пропускная способность и ограничения размера `sendProviderMessage` не документированы. sing-box-for-apple на tvOS использует TCP с секретом вместо сокета в App Group — причина неизвестна. Контейнер на tvOS ограничен `Library/Caches` и может очищаться системой.

**Смягчение.** Канал скрыт за одним протоколом Swift; транспорт заменяем. На tvOS не рассчитывать на долговечное локальное хранение: профили восстановимы из источника.

**Что закроет.** Замер: размер и частота сообщений до деградации на каждой платформе; проверка unix-сокета в контейнере группы на Apple TV; проверка сохранности снимка между запусками.

## R-18. Транзитивные лицензии

**Суть.** Около 100 Go-модулей каждого ядра не аудированы. Одна GPL-зависимость в Xray-сборке разрушает вывод о её лицензионной чистоте.

**Смягчение.** `go-licenses` или аналог в сборочной цепочке; отчёт — артефакт каждой сборки.

**Что закроет.** Отчёт по лицензиям для точного набора тегов и `GOOS` каждого XCFramework.

## R-19. Цепочка поставки

**Суть.** OneXray берёт libXray с `main` и Go `stable`. hiddify скачивает готовые бинарники ядра. sing-box с `with_naive_outbound` линкует готовые библиотеки cronet.

**Смягчение.** Все версии закреплены по SHA. XCFramework не хранится в git, подключается с контрольной суммой. Теги с готовыми бинарниками третьих сторон в базовую сборку не входят.

**Что закроет.** Две независимые сборки из одного набора SHA с совпадающими контрольными суммами, либо документированные причины расхождения.

## R-20. Минимальная ОС для Go 1.27

**Суть.** Какую минимальную macOS и iOS требует Go 1.27 — не проверено. Может поднять минимум macOS выше принятого в ADR-0005.

**Смягчение.** Минимумы в ADR-0005 уже выше, чем у upstream-сборок движков.

**Что закроет.** Release notes Go 1.27 и запуск собранного моста на минимальной поддерживаемой версии каждой ОС.

## R-21. Размер бинарников

**Суть.** Чисел нет. Известны только утяжелители sing-box: cronet, tailscale, openvpn, openconnect, usbip, полный grpc. Старый блоб hiddify — 58,1 МБ на arm64.

**Смягчение.** Сокращённый набор тегов; у каждого тега есть заглушка.

**Что закроет.** Размеры срезов XCFramework для полного и сокращённого набора тегов.

## R-22. Скрипты и HTTPS-инспекция

**Суть.** Интерпретируемый код разрешён с условиями (DPLA 3.3.1(B), Guideline 4.7). Про MITM и CA в правилах ничего нет; DPLA 3.3.5(A) делает профиль с одним CA серой зоной. Ни один движок не даёт MITM — это была бы наша реализация.

**Смягчение.** Вне первого этапа. Когда дойдёт: декларативные модули первыми, узкий API скриптов, инспекция под флагом сборки, на tvOS не предлагается.

**Что закроет.** Отдельное исследование и ADR перед началом работ; прохождение ревью сборкой с этой функцией.
