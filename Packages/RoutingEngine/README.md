# RoutingEngine

Модель правил маршрутизации, её проверка, понижение до плоских правил движка и симулятор. Зависимостей нет, только Foundation.

Роль (решение от 2026-11-25, `Documentation/Architecture/routing-parity.md`): **управляющий слой**. Соединения маршрутизирует движок; этот модуль в путь данных не входит. Он проверяет таблицу, объясняет решения и является источником для компиляции правил в конфиг движка. Семантика сопоставления приведена к маршрутизатору Xray и сверяется с ним дифференциальным тестом.

Состояние: собран и протестирован на Linux (Swift 5.10.1); на платформах Apple не собирался.

## Семантика

- Побеждает первое совпавшее правило. Каждый индекс хранит номер правила; победитель — наименьший номер среди всех совпадений. Для CIDR это значит: выигрывает правило с меньшим номером, а не самый длинный префикс. Самый длинный префикс тоже вычисляется и показывается в объяснении.
- `domainSuffix("example.com")` совпадает с `example.com` и поддоменами по границе метки; `badexample.com` не совпадает. `domainSuffix(".example.com")` — только поддомены. Граница метки — как в Xray-core: `common/geodata/strmatcher/matchers.go`, `DomainMatcher.Match` [VERIFIED]. Поведение sing-box не сверено: его матчер лежит во внешнем модуле `sagernet/sing`, которого нет среди клонов [UNVERIFIED].
- Условие по отсутствующему текстовому или адресному полю запроса ложно, поэтому его булево отрицание `not` истинно. Отсутствующий порт равен 0, как в движке.
- Имя запроса приводится к нижнему регистру и больше не меняется: завершающая точка сохраняется, и `example.com.` не попадает под суффикс `example.com` (так ведёт себя движок). В значениях правил точка отрезается.
- `RoutingTable.domainStrategy`: `asIs` — у соединения с доменом адресов нет; `ipOnDemand` — адресные правила видят `RouteRequest.resolvedIPs`; `ipIfNonMatch` — второй проход с разрешёнными адресами, если первый ничего не нашёл. Адресное правило совпадает, если подходит любой из адресов.
- `ipNotIn([префиксы])` — отрицание адреса в семантике движка: ложно без адреса; адрес учитывается, только если в списке есть префикс его семейства. Это не `not(ipCIDR)`.
- `inboundTag`, `user` — точное сравнение; `sniffedProtocol` — префикс; `sourceCIDR`, `sourcePort` — источник соединения.
- Адрес `::ffff:a.b.c.d` в запросе считается IPv4; префикс `::ffff:…/96+` хранится как IPv4. Семейства адресов между собой не совпадают.
- Имя домена длиннее 253 байт или с пробелом в запросе отбрасывается (поле становится пустым); движок сравнил бы его как текст.
- `ruleSet(tag)` разворачивается при компиляции в «любое из условий набора». Наборы только встроенные: загрузки и разбора `.srs`/geosite здесь нет.
- В индексы попадают правила вида «домен / суффикс / CIDR / порт / сеть» и их `or`. Всё остальное (ключевое слово, regex, `and`, `not`, `ipNotIn`, условия по источнику, входящему, пользователю, протоколу) идёт в упорядоченный список, который просматривается только до номера лучшего найденного индексами правила.

## Понижение

`RuleLowering.lower(table)` возвращает `LoweredTable`: плоские правила в порядке приоритета с тегами `r<номер правила>.<часть>` и список `issues`. `or` по разным полям даёт несколько подряд идущих правил; `not`, И двух условий одного поля и слишком широкие разложения плоской формы не имеют и попадают в `issues` — такую таблицу движку отдавать нельзя. Финальное действие — замыкающее правило «сеть TCP или UDP», кроме `ipIfNonMatch`, где оно должно стать исходящим по умолчанию (`finalIsCatchAllRule == false`).

## Регулярные выражения

Собственный движок вместо `NSRegularExpression` и `Regex`: оба с возвратами, а шаблон приходит из импортированного профиля. sing-box компилирует `domain_regex` пакетом Go `regexp` (`route/rule/rule_item_domain_regex.go`) [VERIFIED], то есть синтаксис RE2 без обратных ссылок и просмотров.

Поддержано подмножество; всё остальное — ошибка компиляции правила, а не тихое несовпадение. Не поддержаны: `\b`, POSIX- и Unicode-классы, не-ASCII в шаблоне, флаги кроме ведущего `(?i)`. Шаблоны с этими конструкциями, допустимые в движках, здесь будут отклонены.

## Известные ограничения

- `ConflictDetector` находит только покрытие одним более ранним правилом (суффикс домена, точный домен, CIDR). Покрытие объединением (два /25 закрывают /24), порты, сети и составные условия не анализируются.
- `RouteSimulator` показывает причины только для первых `traceLimit` правил перед победителем; остальные считаются в `omittedEntries`.
- `geosite:` / `geoip:` и другие внешние наборы не поддержаны; цепочки и состав групп в конфиг движка не компилируются (см. routing-parity.md §4).
- Расход памяти и время построения на больших таблицах — `Documentation/Performance/routing-benchmarks.md`.
- ADR-0004 называет зависимость `RoutingEngine → DomainModels`; `Package.swift` и постановка задачи её не задают. Модуль сделан без зависимостей.
